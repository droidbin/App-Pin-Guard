# 개별 앱 잠금 재설계 수동 검증 절차서

`DESIGN-app-lock-redesign.md` §10의 실기 검증 항목입니다. 로그는 `%LOCALAPPDATA%\WindowsAppProtector.WinUI\Logs`의
`agent.log`, `gate.log`와 관리자 권한이 필요한 `C:\ProgramData\Windows App Protector\Logs\service.log`에서 확인합니다.
`powershell -ExecutionPolicy Bypass -File tools\diag.ps1`로 한 번에 모을 수 있습니다.

## 준비

- [ ] `build_setup.ps1` 성공 (경고 없음), 단위 테스트 통과(`dotnet test tests\UnitTests\UnitTests.csproj`)
- [ ] Chrome, 삼성 인터넷, 카카오톡, 패키지 앱(계산기) 설치 확인
- [ ] 앱별 허용 시간 `0`(앱을 닫을 때까지 해제)으로 시작

## 체크리스트

1. [ ] 크롬을 잠그고 실행 → PIN 창이 **1개**만 뜸. 입력 후 크롬의 모든 창이 보이고 5분 동안 다시 숨겨지지 않음.
2. [ ] 해제된 크롬에서 새 창(Ctrl+N), 바탕화면 아이콘으로 새 실행 → PIN 없이 열림.
3. [ ] 크롬을 모두 닫고 3초 뒤 다시 실행 → PIN을 다시 물음.
4. [ ] 크롬과 삼성 인터넷을 둘 다 잠그고 크롬만 해제 → 삼성 인터넷은 계속 숨겨짐.
5. [ ] 크롬 PIN 창이 떠 있는 상태에서 크롬 아이콘을 여러 번 클릭 → PIN 창은 계속 1개 (`gate.log`에 `gate.unlock.busy`).
6. [ ] 에이전트를 강제 종료해 재시작시킨 직후에도 해제 후 남는 PIN 창이 없음.
7. [ ] 카카오톡 잠금 → 실행 시 PIN, 실행 중 다시 실행 → PIN 없이 기존 창이 뜸. 완전히 종료 후 재실행 → PIN.
8. [ ] 카카오톡을 이름 바꿔 복사한 exe로 실행 → 종료되고 안내가 뜸.
9. [ ] 패키지 앱(계산기) 잠금 → 창 숨김 후 PIN으로 열 수 있음.
10. [ ] 허용 시간 1분, 종료 시 재잠금 끔 → 해제 후 앱 종료·재실행해도 1분 안에는 PIN 없음. 1분 후 창이 숨겨지고 PIN 요청.
11. [ ] PIN 5회 오류 → 제한 메시지, 제한 시간 동안 모든 PIN 창에서 거부.
12. [ ] 서비스 중지 상태에서 잠긴 앱 실행 → 열리지 않음(fail-closed).
13. [ ] 해제 직후 **클릭하지 않고** 마우스만 움직여도(움직이지 않아도) 커서가 보임. 크롬(window 모드)과 카카오톡(launch 모드) 둘 다.
14. [ ] `agent.log`, `gate.log`, `service.log`에 해제·재잠금·PIN 창 이벤트가 앱 이름과 함께 남음.

## 로그에서 볼 키

| 파일 | 키 | 의미 |
|---|---|---|
| `service.log` | `gate.authorize` / `gate.unlock` | PIN 요청 결과(`app=`, `result=`, `session=`) |
| `service.log` | `unlock.ended`, `unlock.pruned` | 앱 종료·시간 만료·정책 변경으로 해제가 끝남 |
| `agent.log` | `agent.unlock.prompt`, `agent.restore` | PIN 창 요청, 숨긴 창 복원 개수 |
| `agent.log` | `agent.unlock.state` | 이 세션에서 해제된 앱 수 |
| `gate.log` | `gate.focus` | 승인 직후와 활성화 직후의 커서 플래그(`cursorFlags=0x1`이면 보임), 전경 프로세스 |

13번이 실패하면 `gate.focus`의 `cursorFlags`와 `foreground` 값을 근거로 원인을 다시 판단합니다(입력 주입 우회책은 쓰지 않습니다).
