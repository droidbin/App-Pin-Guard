# 백엔드 재설계 수동 검증 절차서

`DESIGN-backend-redesign.md` §10의 수동 검증 항목입니다. 관리자 셸이 필요하므로 구현과 별도로 실행합니다.
각 단계 앞뒤로 진단 파일을 만들어 두면 원인 추적이 쉽습니다.

```powershell
powershell -ExecutionPolicy Bypass -File tools\diag.ps1
```

`diag.ps1`은 관리자 권한 없이도 `Runtime\status.json`, 서비스 로그 마지막 200줄, 사용자 로컬 Gate/에이전트 로그,
관리형 IFEO 키 목록, 서비스 상태를 `tools\diag-output.txt` 하나로 모읍니다.

## 준비

- [ ] `build_setup.ps1` 성공 (경고 없음, csc에 `/warnaserror+`)
- [ ] 테스트용 표준 사용자 계정 1개(관리자 아님)와 관리자 계정을 준비
- [ ] 카카오톡 또는 임의의 일반 exe(예: 메모장 복사본), Chrome 설치 확인

## 시나리오

1. **카카오톡 잠금, 차단 모드**
   - 설정에서 "Win32 일반 앱 실행 시 PIN 묻기"를 끄고 카카오톡을 잠급니다.
   - [ ] 카카오톡을 실행하면 "보호 정책에 따라 이 앱의 실행이 차단되었습니다" 안내가 나옵니다.
   - [ ] `status.json`의 해당 앱 `Rule`이 `applied-blocked`입니다.

2. **Gate 모드** (이전에 파이프 때문에 동작하지 않던 경로)
   - "PIN 묻기"를 켜고 같은 앱을 실행합니다.
   - [ ] PIN 창이 나옵니다.
   - [ ] 맞는 PIN이면 앱이 실행되고 `service.log`에 `gate.authorize ... result=Approved`가 남습니다.
   - [ ] 틀린 PIN을 5회 입력하면 대기 시간("N초 후에 다시 시도")이 적용됩니다.
   - [ ] 서비스를 중지한 상태에서 실행하면 "보호 서비스가 응답하지 않아 실행할 수 없습니다"가 나오고 앱은 실행되지 않습니다.

3. **반영 속도**
   - [ ] UI에서 잠금을 저장한 뒤 1초 안에 IFEO 키가 생기고 `status.json`의 `AppliedRevision`이 저장한 `Revision`과 같아집니다.
   - [ ] 서비스를 중지하고 저장하면 "보호 서비스가 아직 변경 사항을 적용하지 않았습니다…" 알림이 뜹니다.

4. **이름 변경·복사 우회**
   - 보호 대상 exe를 `%TEMP%\x.exe`로 복사해서 실행합니다.
   - [ ] 즉시 종료되고 안내(또는 Gate의 PIN 창)가 표시됩니다.
   - [ ] `service.log`에 `watcher.copy.detected`, `watcher.blocked`가 남습니다.
   - [ ] PowerShell에서 `DEBUG_PROCESS` 플래그로 시작해도(IFEO 우회) 같은 결과입니다.

5. **Chrome 잠금**
   - [ ] Chrome을 잠그면 창이 숨겨지고, 해제하면 복원됩니다.
   - [ ] 관리 UI를 종료한 상태에서도 같습니다(숨김 유지, 잠금 해제 시 복원).

6. **에이전트 보호**
   - [ ] 표준 사용자가 작업 관리자로 `WindowsAppProtector.WindowAgent.exe`를 끝내려 하면 거부됩니다.
   - [ ] 관리자가 종료하면 1초 안에 다시 실행되고 창은 숨겨진 채로 유지됩니다. `status.json`의 `Agents[].Restarts`가 늘어납니다.

7. **서비스 재시작**
   - [ ] `sc stop`/`sc start` 후에도 숨긴 창이 깜빡이며 나타나지 않습니다. `service.log`에 `agent.adopted`가 남습니다.

8. **변조 복구**
   - [ ] 관리자가 관리형 IFEO 키(`WindowsAppProtectorManaged=1`)를 지우면 1초 안에 다시 생성됩니다.
   - [ ] `status.json`의 `TamperEvents`에 `IFEO rule restored: ...`가 기록되고 설정 화면 "보호 상태"에 표시됩니다.

9. **충돌**
   - 다른 프로그램이 같은 exe 이름에 `Debugger`를 등록해 둔 상태에서 그 앱을 잠급니다.
   - [ ] 앱 상세 패널에 "다른 프로그램이 이 앱의 실행 설정을 사용하고 있어 잠글 수 없습니다."가 표시됩니다.
   - [ ] `status.json`의 해당 `Rule`이 `conflict`입니다. 다른 프로그램의 키는 건드리지 않습니다.

10. **beta.13에서 업데이트**
    - [ ] 앱 목록, PIN, 잠금 상태가 유지됩니다.
    - [ ] `ProgramData\Windows App Protector\config.json.v2.bak`이 생기고 `config.json`은 없습니다.
    - [ ] `%LOCALAPPDATA%\WindowsAppProtector.WinUI\pin.json`이 삭제됩니다.
    - [ ] `policy.json`, `secrets.json`, `ui.json`이 생기고 `Policy\window-policy.txt`는 없습니다.
    - [ ] 이전 에이전트가 새 에이전트로 교체됩니다(`agent.replaced`).

11. **제거**
    - 설치 폴더의 `Uninstall.bat`을 실행합니다.
    - [ ] 제거 전에 숨겨졌던 창이 모두 복원됩니다.
    - [ ] 관리형 IFEO 키, 서비스, `ProgramData\Windows App Protector` 폴더가 남지 않습니다.

12. **로그**
    - [ ] `Logs\service.log`, `Logs\ui.log`, `%LOCALAPPDATA%\WindowsAppProtector.WinUI\Logs\gate.log`, `agent.log`에서 한글이 깨지지 않습니다.
    - [ ] 로그에 PIN, 해시, 요청 원문이 없습니다.

## 권한 확인 (표준 사용자 셸)

- [ ] `type "%ProgramData%\Windows App Protector\policy.json"` → 접근 거부
- [ ] `type "%ProgramData%\Windows App Protector\secrets.json"` → 접근 거부
- [ ] `dir "%ProgramData%\Windows App Protector\Gate\Requests"` → 접근 거부 (만들기만 허용)
- [ ] `type "%ProgramData%\Windows App Protector\Runtime\status.json"` → 읽힘
- [ ] 위 `Runtime` 폴더에 파일을 만들 수 없음
