# App PIN Guard UI/UX 개편 계획서

작성일: 2026-11-23
대상 버전: 2.1.0 (한 번에 구현해 단일 릴리스)
범위: 관리 앱(`src/WinUI3`), 실행 PIN 창(`src/LaunchGate`), 트레이 메뉴, 설치 후 첫 실행

> **구현 담당 AI에게:** 이 문서는 단계로 나누지 않은 일괄 구현 지시서다. 1~9절은 무엇을 만들지(디자인 명세), 10절은 어떤 순서로 어떤 파일을 바꿀지, 11절은 끝났는지 확인하는 기준, 12절은 미리 확정한 결정이다. 문서에 없는 판단이 필요하면 12절의 원칙을 따르고, 멈춰서 묻지 말고 진행한 뒤 마지막 보고에 적는다. 보호·차단 동작(IFEO, 서비스 동기화, 창 숨김, 핫키, PIN 해시)은 **동작을 바꾸지 않는다.** 바꾸는 것은 화면과 그 화면을 만드는 코드뿐이다.

## 1. 제품을 다시 정의하기

| 항목 | 내용 |
|---|---|
| 제품 | 지정한 Windows 앱을 PIN으로 잠그는 개인용 보안 유틸리티 |
| 주 사용자 | 가족·동료와 PC를 같이 쓰는 사람, 아이 PC를 관리하는 보호자, 업무용 메신저·브라우저를 가리고 싶은 직장인 |
| 화면의 주 역할 | ① 무엇이 잠겨 있는지 한눈에 확인 ② 앱을 몇 번의 클릭으로 잠그고 풀기 ③ 잠긴 앱을 열 때 빠르고 믿음직하게 PIN 받기 |
| 사용 빈도 | 관리 화면은 가끔(설정 시), **PIN 창은 매일 여러 번**. 사용자가 가장 자주 보는 화면은 관리 앱이 아니라 PIN 창이다. |

이 마지막 줄이 개편의 출발점이다. 지금 가장 자주 보이는 실행 PIN 창은 410×190 WinForms 기본 대화상자이고(`LaunchGate/Program.cs:72`), 가장 공들인 화면은 가끔 여는 관리 목록이다. 개편은 이 순서를 뒤집는다.

## 2. 현재 상태 진단

코드 기준(`MainWindow.xaml.cs`, `SettingsDialog.xaml.cs`, `LaunchGate/Program.cs`)으로 정리했다. 실제 화면 캡처는 아직 하지 않았다(관리자 권한·PIN 필요).

### 구조 문제
- **UI가 전부 C# 코드로 조립된다.** XAML 뷰가 없고 `MainWindow.xaml.cs` 한 파일이 2,469줄이다. 색은 `Brush(0x1F, 0x6B, 0x50)` 같은 값이 파일마다 흩어져 있고(`MainWindow.xaml.cs:221,232,284,431`, `SettingsDialog.xaml.cs:25,95,150…`), 다크 모드·고대비 모드를 지원할 방법이 없다.
- 창 크기·여백·코너 값이 화면마다 다르다(코너 4, 버튼 높이 38/40, 패딩 24/12,9).

### 메인 화면 문제
- 상단 툴바에 버튼 6개(파일 추가, 설치 앱, 삭제, 잠금 전환, 전체 잠금, 전체 해제) + 검색줄에 "실행 정책"이 한 줄로 나열된다. 우선순위가 보이지 않는다.
- **"선택 후 버튼" 방식.** 앱 하나를 잠그거나 풀려면 목록에서 고른 뒤 위쪽 "잠금 전환"을 눌러야 한다. 상태 칩(`잠금`/`해제`/`대기`)은 눌러지지 않는다.
- "잠금 전환"과 "전체 잠금"이 같은 아이콘(`\uE72E`)을 쓴다.
- 목록에 앱 아이콘이 없다. 이름과 경로 텍스트만으로 앱을 구별해야 한다.
- 결과·오류가 화면 맨 아래 12px 회색 상태줄 한 줄로만 나온다. 오류도 성공도 같은 모양이라 놓치기 쉽다.
- 빈 목록일 때 안내가 없다.
- `대기` 상태의 의미를 화면 어디에서도 설명하지 않는다.

### 잠금·PIN 문제
- 잠긴 관리 화면은 빈 배경 위 자물쇠 아이콘 + 한 줄 문구이고, PIN은 그 위에 뜨는 ContentDialog("인증")로 받는다. 두 단계로 보인다.
- PIN 입력 실패 횟수, 남은 시도, 대기 시간이 화면에 나오지 않는다.
- 실행 PIN 창(Gate)은 기본 WinForms 컨트롤 그대로라 다른 화면과 전혀 다른 제품처럼 보인다. 어떤 앱을 열려는지 아이콘도 없다.

### 설정 문제
- 설정이 별도 창(900×620)으로 열린다. 관리 화면과 창이 두 개가 된다.
- 실행 정책 대화상자는 `HH:mm`을 텍스트로 직접 쳐야 하고, 검증 실패 시 대화상자가 닫힌 뒤 상태줄에만 오류가 나온다(`MainWindow.xaml.cs` 실행 정책 부분).

## 4. 디자인 방향: "걸쇠(Latch)"

> 물리적인 자물쇠 장치처럼 **잠김은 단단하고 분명하게, 열림은 조용하게** 보이게 한다.

시중 보안 앱은 거의 다 파랑(신뢰)이나 초록(안전)을 쓰고, 지금 우리 앱도 초록(#1F6B50)이다. 우리는 **놋쇠(brass) 색을 "잠김" 상태 전용 색**으로 쓴다. 자물쇠·금고 손잡이·열쇠의 재료색이라 "잠겨 있다"는 뜻을 색만으로 전달하고, Windows 기본 강조색(파랑)과도 겹치지 않는다. 나머지 화면은 차가운 회청색 중립으로 조용하게 둔다.

### 원칙
1. **상태가 주인공이다.** 화면마다 가장 큰 요소는 "지금 잠겨 있는가"이다. 버튼이 아니다.
2. **놋쇠는 잠김에만 쓴다.** 놋쇠색이 보이면 그건 잠겨 있다는 뜻이다. 장식·일반 버튼·링크에는 쓰지 않는다. 일반 주요 버튼은 잉크색(진한 회청)이다.
3. **바로 조작한다.** 선택 후 툴바 버튼 대신, 행 안의 토글과 `…` 메뉴로 그 자리에서 바꾼다.
4. **결과는 일어난 자리에서 말한다.** 하단 상태줄을 없애고, 행 안 변화 + InfoBar(오류) + 짧은 토스트(성공)로 나눈다.
5. **움직임은 한 번만.** PIN이 맞았을 때 걸쇠가 열리는 0.3초 모션 하나만 둔다. 다른 곳엔 Fluent 기본 전환만 쓴다.

## 5. 디자인 토큰

모든 값은 `Themes/Tokens.xaml`의 `ThemeDictionaries`(Light / Dark / HighContrast)로 정의하고, 코드에서는 `{ThemeResource}` 이름으로만 참조한다. 하드코딩 색은 0개가 목표다.

### 색

| 토큰 | Light | Dark | 용도 |
|---|---|---|---|
| `InkBrush` | `#1A2330` | `#E8ECF1` | 본문 글자, 주요 버튼 배경(라이트) |
| `InkMutedBrush` | `#5B6676` | `#9AA5B4` | 경로·보조 설명 (대비 4.5:1 이상) |
| `SurfaceBrush` | `#FFFFFF` (Mica 위 레이어) | `#232831` | 목록·설정 카드 면 |
| `CanvasBrush` | Mica Alt (대체색 `#EEF1F5`) | Mica Alt (대체색 `#171B21`) | 창 바탕 |
| `LatchBrush` (놋쇠) | `#9A6414` | `#E3AE52` | 잠김 상태 칩·토글 켜짐·잠금 화면 걸쇠 |
| `LatchSubtleBrush` | `#F6EBD7` | `#3A2F1C` | 잠김 칩 배경, 잠긴 행의 아이콘 받침 |
| `DangerBrush` | `#B3261E` | `#FF8A80` | PIN 오류, 삭제 확인 |
| `DividerBrush` | `#E1E5EB` | `#2F3540` | 행 구분선 |

- `#9A6414`는 흰 바탕 대비 약 4.9:1로 작은 글자에도 쓸 수 있다. 다크의 `#E3AE52`도 `#232831` 위 4.5:1 이상. 구현 시 대비 검사기로 다시 확인한다.
- 고대비 테마에서는 모든 토큰을 시스템 색(`SystemColorHighlightColor` 등)으로 대체한다. 놋쇠도 버린다.
- "열림/해제" 상태는 색을 쓰지 않는다. 회색 외곽선 자물쇠 아이콘과 글자만 쓴다. 색이 없는 게 곧 "열림"이다.

### 글꼴

| 역할 | 글꼴 | 크기 / 굵기 / 줄간격 |
|---|---|---|
| 전체 UI (한글·영문·숫자) | **Pretendard Variable** (OFL, 앱에 번들) | — |
| 화면 제목 | Pretendard | 28 / SemiBold / 36 |
| 섹션 제목 | Pretendard | 20 / SemiBold / 28 |
| 앱 이름(행) | Pretendard | 15 / Medium / 22 |
| 본문 | Pretendard | 14 / Regular / 21 |
| 보조(경로, 설명) | Pretendard | 12 / Regular / 18 |
| PIN 자리 표시 | Pretendard, 고정폭 숫자(`tnum`) | 32 / SemiBold |

- 지금은 `Noto Sans CJK KR`을 지정했지만 번들되어 있지 않아 대부분 PC에서 맑은 고딕으로 떨어진다(`Assets/Fonts/README.md`). Pretendard는 한글 UI용으로 만들어져 Segoe UI Variable과 영문 비율이 비슷하고, 한 가족으로 위계를 다 만들 수 있다.
- 두 번째 서체는 쓰지 않는다. 위계는 크기와 굵기로만 만든다.

### 간격·형태

| 토큰 | 값 |
|---|---|
| 간격 단위 | 4 (4 / 8 / 12 / 16 / 24 / 32 / 48) |
| 창 좌우 여백 | 32 (컴팩트 폭에서 16) |
| 목록 행 높이 | 64 (아이콘 32) |
| 코너 | 컨트롤 4, 목록 면·설정 카드 8, 잠금 화면 PIN 칸 8, 창 Mica 기본 |
| 그림자 | 사용하지 않음. 면 구분은 Mica 위 흰 레이어 + 1px `DividerBrush` |

코너를 위계별로 다르게 둔다. 모든 요소에 같은 둥근 카드를 씌우지 않는다.

## 6. 정보 구조

```
App PIN Guard
├─ 보호 앱          (기본 화면)
│   └─ 앱 상세      (오른쪽 패널: 실행 정책, 전용 PIN, 경로, 삭제)
└─ 설정
    ├─ 보안         PIN 변경, 자동 잠금(유휴 분), 실행 시 PIN 묻기
    ├─ 일반         Windows 시작 시 실행, 트레이 동작
    ├─ 단축키
    └─ 업데이트·정보 채널, 버전, 업데이트 확인
```

- 활동 기록(ROADMAP-NEXT의 '잠금 이력')은 서비스 쪽 기록이 생긴 뒤 추가한다. 이번 범위가 아니다.
- 별도 설정 창을 없애고 NavigationView(왼쪽 레일, 접힘 가능) 안 페이지로 옮긴다.
- 헤더의 아이콘 버튼 3개(업데이트 확인·설정·종료)는 사라진다. 업데이트 확인은 설정 > 업데이트로, 종료는 트레이 메뉴와 레일 하단 `…`로 간다.

## 7. 화면별 설계

### 7.1 창 틀
- `ExtendsContentIntoTitleBar = true`, Mica Alt 배경, 제목 표시줄에 앱 아이콘 + "App PIN Guard"만.
- 제목 표시줄 오른쪽(캡션 버튼 왼쪽)에 **"지금 잠그기"** 버튼 하나. 누르면 관리 화면이 즉시 잠금 화면으로 바뀌고 모든 보호 앱이 잠긴다. 자리 비울 때 가장 자주 하는 동작을 어디서든 한 번에.

### 7.2 보호 앱 (기본 화면)

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🔒 App PIN Guard                                  [지금 잠그기]  _ □ × │
├────┬─────────────────────────────────────────────────────────────────┤
│ ▣  │  보호 앱                                                          │
│ ◷  │  앱 7개가 잠겨 있습니다. 보호 서비스 정상 작동 중.                     │
│    │                                                                 │
│    │  [＋ 앱 추가 ▾]   [🔍 앱 검색                    ]   [모두 잠그기 ▾] │
│    │  ┌─────────────────────────────────────────────────────────────┐ │
│    │  │ [ic] KakaoTalk                          10분 유예   ●━━ 잠김 │ │
│    │  │      C:\Program Files\Kakao\KakaoTalk.exe               …   │ │
│    │  ├─────────────────────────────────────────────────────────────┤ │
│    │  │ [ic] Chrome                                         ●━━ 잠김 │ │
│    │  │      C:\Program Files\Google\Chrome\…\chrome.exe       …   │ │
│    │  ├─────────────────────────────────────────────────────────────┤ │
│    │  │ [ic] 메모장                                          ━━○ 열림 │ │
│    │  │      C:\Windows\System32\notepad.exe                    …   │ │
│    │  └─────────────────────────────────────────────────────────────┘ │
│ ⚙  │                                                                 │
└────┴─────────────────────────────────────────────────────────────────┘
```

- **상단 상태 문장**: "앱 N개가 잠겨 있습니다." + 서비스 상태. 서비스가 꺼져 있거나 정책 동기화가 실패하면 이 자리가 경고 InfoBar로 바뀌고 "서비스 다시 시작" 버튼을 붙인다. (지금은 `StatusText`에 묻혀 있는 정보다.)
- **앱 추가**는 SplitButton 하나: 기본 동작은 "설치된 앱에서 고르기", 드롭다운에 "실행 파일 직접 찾기". 지금의 "파일 추가"·"설치 앱" 두 버튼을 합친다. 설치 앱 고르기는 아이콘 있는 검색 가능 목록 + 다중 선택.
- **행**: 앱 아이콘(실행 파일에서 추출, 패키지 앱은 로고) / 이름 / 경로 / 정책 요약 태그("10분 유예", "22:00–07:00") / **토글** / `…` 메뉴.
  - 토글 켜짐 = 놋쇠색 + "잠김", 꺼짐 = 회색 + "열림". 행 클릭 = 오른쪽 상세 패널.
  - `…` 메뉴: 실행 정책, 폴더에서 보기, 목록에서 제거.
  - 잠긴 행은 아이콘 받침이 `LatchSubtleBrush`. 목록을 훑으면 잠긴 앱만 따뜻하게 보인다.
- **모두 잠그기 ▾**: "모두 잠그기 / 모두 열기". 지금의 "전체 잠금"·"전체 해제" 두 버튼을 합친다.
- "삭제"·"잠금 전환" 툴바 버튼은 없앤다(행 안으로 이동). 다중 선택 시에만 목록 위에 "선택한 3개: 잠그기 / 열기 / 제거" 막대가 나타난다.
- **빈 상태**: 자물쇠 일러스트 대신 실제 동작을 안내한다.
  "아직 보호 중인 앱이 없습니다. 잠그고 싶은 앱을 추가하면 실행할 때 PIN을 묻습니다." + [설치된 앱에서 고르기] 버튼.
- **검색 결과 없음**: "‘카카오’와 일치하는 앱이 없습니다." + [검색 지우기].

### 7.3 앱 상세 패널 (실행 정책)

목록 오른쪽에 열리는 360px 패널(좁은 창에서는 전체 화면 페이지). 지금의 실행 정책 ContentDialog를 대체한다.

```
 [ic] KakaoTalk                       잠김 ●━━
 C:\Program Files\Kakao\KakaoTalk.exe

 PIN
  (•) 기본 PIN 사용
  ( ) 이 앱 전용 PIN     [ 새 PIN        ]

 다시 묻기까지
  [ 실행할 때마다 ▾ ]   (실행할 때마다 / 5분 / 10분 / 30분 / 1시간 / 직접 입력)
  [✓] 앱을 모두 닫으면 바로 다시 잠그기

 잠그는 시간
  ( ) 항상
  (•) 정해진 시간에만   [22:00] ~ [07:00]   (TimePicker)

                                  [목록에서 제거]   [저장]
```

- `HH:mm` 직접 입력 → TimePicker. 분 입력 → 선택형 콤보.
- 입력 오류는 해당 칸 바로 아래 빨간 글자로 표시하고 패널을 닫지 않는다.
- "0분이면 실행할 때마다…" 같은 규칙 설명 문단은 선택지 이름 자체로 대체한다("실행할 때마다").

### 7.4 잠금 화면 (관리 앱)

ContentDialog를 쓰지 않는다. 잠겨 있을 때 창 전체가 이 화면이다.

```
┌──────────────────────────────────────────────┐
│                                              │
│                    ┌──┐                      │
│                    │🔒│  ← 놋쇠 걸쇠 아이콘     │
│                    └──┘                      │
│              App PIN Guard                   │
│          PIN을 입력해 관리 화면을 여세요          │
│                                              │
│          [ •  •  •  •  _  _ ]                │
│                                              │
│          PIN이 틀렸습니다. 2번 더 틀리면          │
│          30초 동안 입력할 수 없습니다.            │
│                                              │
│                            [PIN을 잊었나요?]   │
└──────────────────────────────────────────────┘
```

- PasswordBox 하나를 PIN 칸 모양으로 표시. 숫자 키 입력 즉시 반영, Enter로 확인, 4자리 이상이면 확인 버튼 활성.
- 실패: 칸이 짧게 좌우로 흔들리고(감속 동작 켜면 생략) 남은 시도를 글로 표시. 서비스가 시도 횟수를 갖도록 바뀌면(ROADMAP 서비스 중심 상태) 그 값을 그대로 보여 준다.
- 성공: 걸쇠 아이콘의 고리가 위로 열리는 0.3초 모션 → 관리 화면으로 크로스페이드. **이 앱에서 유일한 연출 모션.**
- "PIN을 잊었나요?": 복구 방법(관리자 계정으로 재설치 등)을 안내하는 TeachingTip. 지금은 안내가 없다.

### 7.5 실행 PIN 창 (LaunchGate) — 가장 중요한 화면

잠긴 앱을 실행하면 뜨는 창. 사용자가 하루에 가장 많이 보는 화면이므로 개편의 중심이다.

```
┌─────────────────────────────────────┐
│  ┌────┐                             │
│  │ ic │  KakaoTalk                   │
│  └────┘  잠긴 앱입니다                │
│                                     │
│  [ •  •  •  •  _  _ ]               │
│                                     │
│  [✓] 10분 동안 다시 묻지 않기           │
│                                     │
│               [취소]   [열기]         │
└─────────────────────────────────────┘
  440 × 260, 화면 중앙, 항상 위, 테두리 8 코너
```

- 열려는 앱의 **아이콘과 이름을 크게** 보여 준다. 지금은 "OOO 실행 PIN을 입력하세요." 한 줄뿐이다.
- 앱 정책에 유예 시간이 있으면 체크박스로 보여 주고, 없으면 숨긴다.
- 버튼 이름은 동작 그대로: "실행" → **"열기"**, 결과 메시지도 "열었습니다"로 맞춘다.
- 기술 선택: Gate는 관리자 권한 없이 **빨리 떠야** 한다. WinUI 3는 콜드 스타트가 느리고 런타임 의존성이 크다. 그래서 **WinForms를 유지하되 직접 그리는(owner-draw) 창**으로 같은 토큰(색·Pretendard·코너)을 적용한다(12절 확정). Pretendard는 `PrivateFontCollection`으로 Gate 실행 파일 옆 폰트 파일에서 읽고, 없으면 `Malgun Gothic`으로 대체한다. 목표: 클릭 후 300ms 안에 창 표시.
- Windows 다크 모드를 따라간다(레지스트리 `AppsUseLightTheme` 읽기).

### 7.6 PIN 설정 (첫 실행)

첫 실행 흐름을 화면 3장으로 만든다(ContentDialog 반복 대신 창 안 페이지). PIN이 아직 없을 때만 나온다.

1. **PIN 만들기** — "앱을 열 때 사용할 PIN을 정하세요. 4자리 이상 숫자입니다." 새 PIN → 확인 입력. 불일치는 칸 아래 즉시 표시.
2. **잠글 앱 고르기** — 설치된 앱 목록에서 자주 잠그는 앱(메신저, 브라우저, 사진, 메일)을 위로 올려 체크박스로 고른다. 건너뛰기 가능.
3. **완료** — "앱 3개를 잠갔습니다. 다음에 열 때 PIN을 묻습니다." + [Windows 시작 시 자동 실행] 토글(기본 켜짐) + [시작하기].

### 7.7 설정

PowerToys식 SettingsCard(CommunityToolkit `SettingsControls`)로 구성. 카드 하나 = 설정 하나 = 한 문장 설명.

| 그룹 | 항목 | 컨트롤 |
|---|---|---|
| 보안 | PIN 변경 | 버튼 → 잠금 화면과 같은 PIN 입력 흐름 |
| | 자리를 비우면 자동 잠금 | 콤보(사용 안 함/5/10/15/30분) |
| | 일반 앱(Win32) 실행 시 PIN 묻기 | 토글 + "실험 기능" 태그 |
| 일반 | Windows 시작 시 자동 실행 | 토글 |
| | 창을 닫으면 트레이로 숨기기 | 토글 |
| 단축키 | 각 단축키 | 키 입력 상자(지금 구조 유지, 충돌 시 카드 안 경고) |
| 업데이트·정보 | 업데이트 채널 | 라디오(정식/베타) |
| | 현재 버전 / 업데이트 확인 | 버튼, 결과를 카드 안에 표시 |

- "저장" 버튼을 없애고 바꾸는 즉시 적용한다(Windows 설정과 같은 방식). 적용 실패만 카드 안 오류로 알린다.

## 10. 구현 순서

한 번의 작업으로 끝까지 구현한다. 아래 순서는 의존 관계 때문에 정한 작업 순서일 뿐, 중간 릴리스 단위가 아니다. 각 항목이 끝날 때마다 빌드가 통과해야 다음으로 넘어간다(`build_winui3.bat` 또는 `dotnet build src/WinUI3/WindowsAppProtector.WinUI.csproj -c Release -p:Platform=x64`).

1. **토큰·폰트·스타일.** `Themes/Tokens.xaml`, `Themes/Controls.xaml` 작성, `App.xaml`에 병합, Pretendard 번들(csproj에 `Content` + `CopyToOutputDirectory`).
2. **공용 서비스.** `IconService`, `INotificationService`/`NotificationService`, `PinInput` 컨트롤.
3. **창 틀과 내비게이션.** `MainWindow`에 Mica Alt, `ExtendsContentIntoTitleBar`, 제목 표시줄 '지금 잠그기', NavigationView(보호 앱 / 설정), InfoBar 영역. 잠금 상태면 NavigationView 대신 `LockPage`를 보여 준다(기존 `SetSessionUnlocked` 흐름에 연결).
4. **잠금 화면·첫 실행.** `LockPage`(기존 PIN 검증·시도 제한 로직 재사용), `OnboardingPage`(PIN이 없을 때). 기존 ContentDialog 기반 PIN UI 제거.
5. **보호 앱 화면.** `AppsPage`: 상태 문장, 앱 추가 SplitButton(설치 앱 선택 창은 아이콘 + 검색 + 다중 선택), 검색, 모두 잠그기/열기, 아이콘 행 + 토글 + `…` 메뉴, 다중 선택 막대, 빈 상태·검색 결과 없음. 기존 툴바 버튼 제거.
6. **앱 상세 패널.** `AppDetailPane` + `AppDetailViewModel`: 기존 실행 정책 저장 경로(`MainViewModel`의 정책 저장 메서드)를 그대로 호출. TimePicker, 다시 묻기 콤보, 칸별 오류 표시.
7. **설정 페이지.** `SettingsPage` + `SettingsViewModel`: 7.7 표대로 SettingsCard 구성, 변경 즉시 저장(기존 설정 저장 메서드 재사용). 별도 설정 창과 `SettingsDialog.xaml.cs` 제거, 핫키 재등록은 설정 변경 시점에 호출.
8. **트레이 메뉴.** 7.8 구성으로 메뉴 항목·문구 변경. 기존 트레이 아이콘 생성 코드 재사용.
9. **LaunchGate.** `GateTheme.cs`, `GateForm.cs` 작성, `Program.Prompt()`가 `GateForm`을 쓰도록 변경. 앱 아이콘은 `Icon.ExtractAssociatedIcon`, 유예 시간 체크박스는 정책 값이 이미 전달되는 경우에만 표시(새 프로토콜 필드는 추가하지 않는다). 폰트 파일을 Gate 출력 폴더에도 복사하도록 빌드·설치 스크립트(`build_setup.ps1`, `build_distribution.ps1`) 수정.
10. **문구 일괄 정리.** 8절 표 적용. `\uXXXX` 이스케이프로 된 한글 문자열을 손대는 김에 일반 한글 리터럴로 바꾼다(파일은 UTF-8).
11. **정리·검증.** 하드코딩 색 검색(`Color.FromArgb`, `#[0-9A-Fa-f]{6}`, `Brush(0x`)이 `Themes/`·`GateTheme.cs` 밖에서 0건인지 확인, `tests/UnitTests` 실행, 11절 체크리스트로 자체 점검, `docs/qa/2.1.0-ui.md`에 수동 QA 체크리스트 작성.

## 12. 확정된 결정

구현 중 묻지 않도록 미리 정한다.

1. **강조색**: 놋쇠(`LatchBrush`) 브랜드 고정. Windows 시스템 강조색은 따르지 않는다. 단 고대비 테마에서는 시스템 색으로 대체.
2. **Gate 기술**: owner-draw WinForms. WPF·WinUI로 바꾸지 않는다.
3. **트레이 종료**: 지금 코드의 동작 그대로 유지.
4. **제품명**: 화면에는 `ProductBrand.Name`("App PIN Guard")만 쓴다. 이 상수를 바꾸지 않는다.
5. **활동 기록 페이지**: 이번 구현에서 제외한다. 서비스 쪽 기록이 아직 없어서 화면만 만들면 빈 페이지가 된다. NavigationView에 항목을 넣지 않는다.
6. **버전 번호**: csproj의 `Version`은 건드리지 않는다. 릴리스 시점에 따로 올린다.
7. **새 의존성**: `CommunityToolkit.WinUI.Controls.SettingsControls`만 추가한다. 상세 패널은 기본 `Grid` + `SplitView`로 만들고 다른 패키지는 추가하지 않는다.
8. **문서에 없는 판단**: Fluent 기본 컨트롤과 기본 동작을 우선한다. 놋쇠색은 잠김 상태에만 쓴다(4절 원칙 2). 판단한 내용은 최종 보고에 목록으로 남긴다.
